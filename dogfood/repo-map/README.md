# repo-map dogfood inputs (Section 52.1)

Real CLI dogfood project: **repository inventory** with text and JSON output.
The first domain command is added **manually** after `foundry generate` (growth
recipe in generated `docs/architecture.md`).

## Purpose

1. Exercise Foundry generate for a non-fixture, Appendix-B-shaped Project Spec.
2. Prove the post-generate growth path: responsibility package + Cobra subcommand.
3. Seed REQ-247 measurements (orientation, first-feature diff, retained files).

## Non-goals

- **Not** catalog content — inventory code is never generated by Foundry.
- **Not** the independent long-lived repo itself — generate into a private temp
  parent; keep this directory as reproducible inputs only.
- **Not** greet/demo scaffolding (FND-014).

## Overlay files (`testdata/overlay/`)

| Path | Role |
| ---- | ---- |
| `internal/inventory/` | Domain: walk a path; text/JSON inventory (no Cobra) |
| `internal/cli/inventory.go` | `newInventoryCmd` constructor; Cobra confined to `internal/cli` |

Tests patch generated `internal/cli/root.go` to `AddCommand(newInventoryCmd())` —
the same one-line growth step an agent applies by hand after reading
`AGENTS.md` + `docs/architecture.md`.

## Acceptance signal

Generate `repo-map` → apply overlay → `go test ./...` green →
`repo-map inventory --output text|json` lists files. Zero mandatory deletions of
generated non-test files (FND-014).
